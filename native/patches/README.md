# Patches to termux/proot

`build-proot.sh` applies every `proot-*.patch` here, in name order, to the pinned proot commit.
The bug fixes (0002, 0004, 0005, 0006, 0007) should be offered upstream and removed once a pinned commit
contains them; 0003 is Flatdroid's own hardening. Re-check each one whenever `PROOT_COMMIT` changes
(last checked at 0e42875, 2026-11-23: 0002, 0004 and 0005 still needed; the former 0001, `fork` as
`clone`, is upstream since 9bd5307).

| Patch | What it does | Upstream |
|---|---|---|
| `proot-0002-seccomp-faccessat2-as-faccessat.patch` | Android's app seccomp filter blocks `faccessat2(2)` before Android 16, and proot answers it with `ENOSYS`. glibc then emulates the flags itself, but musl fails with `EINVAL` for `AT_SYMLINK_NOFOLLOW`, which GLib's `g_file_query_exists()` reports as a missing file, so in Alpine flatpak saw no installed apps ("No installed refs found"). The patch re-issues a trapped `faccessat2` as `faccessat(dirfd, path, mode)` when the flags are only `AT_EACCESS` and/or `AT_SYMLINK_NOFOLLOW`; other flags still get `ENOSYS`. Results match proot's own untrapped handling of `faccessat2`, which already follows the final symlink. | not yet offered |
| `proot-0003-non-dumpable.patch` | Hardening, not a bug fix. proot runs as the app's user, as everything it traces does, so a traced process could open `/proc/<proot pid>/mem` (a plain `open()`, which no seccomp filter can tell apart) or use `ptrace`/`process_vm_*` on proot and run code outside its path translation. The patch makes proot non-dumpable at start (the kernel then refuses all three to same-user processes, and Android's `/proc` hides proot from them) and sets the first tracee dumpable again before its `execve(2)`: the kernel refuses a tracer access to a non-dumpable tracee's memory, so that first `execve` couldn't be translated. The shm helper is proot run again, so it is non-dumpable too. | not planned (a project-specific choice) |
| `proot-0004-seccomp-keep-sysexit-on-skipped-enter.patch` | On kernels that run seccomp before ptrace's syscall-entry stop (Linux before 4.8: most Android 7 to 9 devices, and later Android versions on those kernels), proot handles a syscall's entry at its seccomp stop and then skips the ptrace entry stop that follows. That skipped stop went through the "sysexit" branch first, which cleared `sysexit_pending`. For `clone(2)` (`force_fork_sysexit()` asks for its exit) the `PTRACE_EVENT_CLONE` stop in between then restarted the parent with `PTRACE_CONT`, its exit stop was lost, and the next seccomp stop aborted proot (`event.c: assertion "IS_IN_SYSENTER(tracee)" failed`) as soon as a program started a thread (Flatpak, `appstreamcli`). The patch leaves `sysexit_pending` alone on the skipped stop. One file. | not yet offered |
| `proot-0005-seccomp-readlink-as-readlinkat.patch` | Android 8's x86_64 app seccomp filter traps `readlink(2)` (bionic only uses `readlinkat`), and proot answers trapped syscalls it doesn't handle with `ENOSYS`. musl and glibc both call `readlink` on x86_64, so every `readlink(3)` and `realpath(3)` through a link failed in Alpine and in apps (PulseAudio couldn't find its runtime folder). The patch re-issues a trapped `readlink` as `readlinkat(AT_FDCWD, path, buf, size)`, like proot's existing `access` and `mkdir` cases. No effect on aarch64, which has no `readlink` syscall, or on Android 9 and later. | not yet offered |
| `proot-0006-link2symlink-faked-links-dt-unknown.patch` | Upstream's 1ce2525 gives a faked hard link the `d_type` of its file in `getdents(2)` results, so programs that trust `d_type` don't take it for a symlink. To find that type it reads the intermediate and `lstat`s the file, both in the l2s directory, for every listed link. With a Flatpak installation that directory holds about 190,000 entries, and each lookup there took 0.3 to 0.45 ms on a Cortex-A53, so the walk OSTree makes when pruning after every update and uninstall went from 20 s to 150 to 170 s. The patch reports such links as `DT_UNKNOWN` instead (allowed by `getdents`; programs then call `lstat`, which link2symlink answers with the file), found with one `readlink` of the listed entry. The walk is back to 19 s. | not yet offered |
| `proot-0007-exitkill-with-kill-on-exit.patch` | With `--kill-on-exit`, tracees also get `PTRACE_O_EXITKILL`, so they die with PRoot if PRoot itself is killed or crashes. Without it the kernel releases them, and the system call each was stopped in goes on with its original arguments: untranslated, on the host's own paths (a read of a host file outside the guest succeeded every time right after a kill). Every later trapped call gets `ENOSYS`. Linux 3.8 and later. | not yet offered |
